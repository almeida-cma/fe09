Laboratório 1 Relacionado ao Bug 1 (Botão de Orçamento)

Chamada de Função no HTML x Nome Declarado

Quando usamos o atributo onclick="minhaFuncao()" em uma tag HTML, o navegador procura exatamente essa função no JavaScript. Se houver qualquer divergência de digitação, o JavaScript não adivinha e acusa que a função não existe.

O Erro do Console quando o nome não bate: Uncaught ReferenceError: enviarPedido is not defined at HTMLButtonElement.onclick
snippet-lab1.html 
<!DOCTYPE html>
<html>
<body>
  <h3>Pizzaria Dev</h3>
  <!-- ERRO: O onclick chama enviarPedido(), mas o script declarou assarPizza() -->
  <button onclick="enviarPedido()">Pedir Pizza</button>

  <script>
    function assarPizza() {
      alert("🍕 Pizza enviada para o forno!");
    }
  </script>
</body>
</html>

Experimento no OneCompiler:

  1. Copie o código acima, cole no OneCompiler e clique em Run.
  2. Clique no botão "Pedir Pizza". Nada acontece na tela.
  3. Olhe a aba Console: o erro ReferenceError aparece na hora.
Como consertar: Faça o nome do onclick no HTML ser idêntico ao da função no JavaScript:
<button onclick="assarPizza()">Pedir Pizza</button>

Laboratório 2 Relacionado ao Bug 2 (Campo de Nome)

Buscando Elementos por ID e Lendo .value

O método document.getElementById("id-aqui") precisa receber o mesmo ID colocado no HTML. Se o ID estiver errado, o método devolve null (nada). Tentar ler null.value quebra a aplicação imediatamente.

O Erro do Console quando o ID não existe: Uncaught TypeError: Cannot read properties of null (reading 'value')
snippet-lab2.html 
<!DOCTYPE html>
<html>
<body>
  <h3>Escolha o Sabor</h3>
  <!-- O input tem id="sabor" -->
  <input type="text" id="sabor" placeholder="Digite o sabor">
  <button onclick="confirmar()">Confirmar</button>

  <script>
    function confirmar() {
      // ERRO: Procurou "sabor-pizza", mas no HTML só existe "sabor"
      let campo = document.getElementById("sabor-pizza");
      let texto = campo.value; // QUEBRA AQUI!
      alert("Sabor: " + texto);
    }
  </script>
</body>
</html>

Experimento no OneCompiler:

  1. Cole o código no OneCompiler, digite um sabor e clique em "Confirmar".
  2. O alerta não aparece e o console acusa Cannot read properties of null.
Como consertar: Alinhe o ID da busca com o ID que está na tag <input>:
let campo = document.getElementById("sabor");

Laboratório 3 Relacionado ao Bug 3 (Card de Preço)

Eventos do Mouse: mouseover e mouseout

Para criar efeitos que reagem à passagem do mouse sem precisar clicar, usamos mouseover (cursor entra) e mouseout (cursor sai). O erro comum é usar click ou esquecer de registrar o retorno com mouseout.

O Sintoma: Bug Silencioso
Nenhum erro aparece em vermelho no console, mas o elemento não reage ao passar o mouse.
snippet-lab3.html 
<!DOCTYPE html>
<html>
<body>
  <div id="card" style="padding:20px; background:#ddd; width:180px;">Pizza 4 Queijos</div>

  <script>
    let card = document.getElementById("card");

    // ERRO: Usou "click" para um efeito de passar o mouse!
    card.addEventListener("click", destacar);

    function destacar() {
      this.style.background = "#fef08a"; // Amarelo
    }

    function restaurar() {
      this.style.background = "#ddd"; // Volta ao normal
    }
  </script>
</body>
</html>
Como consertar: Troque o evento para mouseover e adicione a escuta do mouseout:
card.addEventListener("mouseover", destacar);
card.addEventListener("mouseout", restaurar);

Laboratório 4 Relacionado ao Bug 4 (Cálculo de Desconto)

O Retorno de Funções (return) e .toFixed()

Uma função que faz um cálculo precisa usar a instrução return para entregar o resultado de volta. Se o return for esquecido, a função entrega undefined. Ao tentar formatar o número com .toFixed(), o código quebra.

O Erro do Console por falta de return: Uncaught TypeError: Cannot read properties of undefined (reading 'toFixed')
snippet-lab4.html 
<!DOCTYPE html>
<html>
<body>
  <button onclick="calcular()">Calcular Pedido</button>
  <p id="total"></p>

  <script>
    function calcularTaxaEntrega(precoBase) {
      let taxa = 6.00;
      let total = precoBase + taxa;
      // ERRO: Faltou entregar o total com "return total;"!
    }

    function calcular() {
      let resultado = calcularTaxaEntrega(40.00); 
      // Como resultado é undefined, toFixed(2) quebra o programa:
      document.getElementById("total").textContent = "Total: R$ " + resultado.toFixed(2);
    }
  </script>
</body>
</html>
Como consertar: Basta adicionar return total; antes do fechamento da função de cálculo:
function calcularTaxaEntrega(precoBase) { ... return total; }

Laboratório 5 Relacionado ao Bug 5 (Contador de Caracteres)

Contadores com for e .length

Para contar letras de uma string com um laço for, o índice i precisa caminhar do 0 até o comprimento do texto (texto.length). Se a condição de parada já começar falsa (ex: i < 0), o laço nunca roda e o total fica em zero.

O Sintoma: Contador travado
Ao digitar na caixa de texto, o contador fica preso em "0 letras" (mesmo após digitar várias palavras).
snippet-lab5.html 
<!DOCTYPE html>
<html>
<body>
  <textarea id="obs" oninput="atualizar()"></textarea>
  <div id="contagem">0 caracteres</div>

  <script>
    function contarTexto(texto) {
      let total = 0;
      // ERRO: i começa valendo 0. Como 0 < 0 é FALSO, o bloco nunca roda!
      for (let i = 0; i < 0; i++) {
        total = total + 1;
      }
      return total;
    }

    function atualizar() {
      let valor = document.getElementById("obs").value;
      let totalLetras = contarTexto(valor);
      document.getElementById("contagem").textContent = totalLetras + " caracteres";
    }
  </script>
</body>
</html>
Como consertar: Faça a condição comparar com o tamanho da string (.length):
for (let i = 0; i < texto.length; i++) {
